## 1. Физическая структура бланка

Один лист A4, портрет. Заголовок по центру: `MAFIA PATTAYA FOXX`.
Три печатных блока + свободная зона.

### Блок A — «РОЛИ НА ИГРУ» (левый верх)
Таблица 2 колонки × 12 строк: `РОЛЬ ИГРОКА` (печатно) | `ИМЯ ИГРОКА` (от руки).

Печатные строки ролей, сверху вниз:
`ДОН МАФИИ` · `МАФИЯ 1` · `МАФИЯ 2` · `МАФИЯ 3` · `МАНЬЯК` · `НАГНЕТАТЕЛЬ` ·
`ОБОРОТЕНЬ` · `КОМИССАР` · `ДОКТОР` · `НАСЛЕДНИК` · `КАМИКАДЗЕ` · `МИРНЫЕ`

### Блок B — «ГОЛОСОВАНИЕ» (правый, основной)
Колонка `№ / ИМЯ` + **7** колонок `ДЕНЬ 1` … `ДЕНЬ 7`. Строки печатно `1)` … `20)`.

### Блок C — «НОЧНЫЕ СОБЫТИЯ» (низ)
Колонка `РОЛЬ` + **7** колонок `НОЧЬ 1` … `НОЧЬ 7`.
Печатные строки: `МАФИЯ` · `ДОН МАФИИ` · `МАНЬЯК` · `НАГНЕТАТЕЛЬ` · `КОМИССАР` · `ДОКТОР`

> Порядок строк блока C **не совпадает** с порядком пробуждения (§4) и с порядком блока A:
> `МАФИЯ` напечатана выше `ДОН МАФИИ`, хотя дон просыпается раньше. Читать строки по
> подписи, не по позиции.

### Зона D — свободное поле (левый низ, под блоком A)
Здесь ведущий от руки ведёт **список мирных** (§2.2) и дописывает роли, которых нет в
печатном списке. Ниже, крупно — **номер партии** (§2.9).

## 2. Правила заполнения — по времени партии

### 2.0. Формат клетки имени: `ИМЯ (МЕСТО)`
Во всех пяти листах ведущий пишет в блоке A и в списке мирных **имя и номер места в
скобках**: `KAZAR (7)`, `AMBER (5)`, `ЛЕНА (8)`, `РАФАЭЛЬ (5)`.

Это ключ связи блоков: блок A связан с блоком B **не по имени, а по явному номеру места**.
Извлечение обязано парсить скобку и использовать её как `seat_no`, а имя — только для
сверки. Расхождение «имя в блоке A ↔ имя на этом месте в блоке B» — конфликт на A1.

### 2.1. До раздачи карт: отметить, каких ролей нет (00:05–00:38)
Ведущий знает состав колоды и помечает в блоке A роли, которых в партии не будет:
**зачёркивает печатный ярлык** (иногда стрелкой) **и рисует прочерк «—» в клетке имени**.

> «Вот здесь ты можешь вычеркнуть те роли, которых не будет… И у тебя остаются окошки
> только для тех ролей, которые будут на игре». (00:17, 00:33)

**Прочерк в клетке имени — единственный надёжный признак «роли нет в партии».**
Зачёркивание ярлыка само по себе таким признаком **не является** (§2.6).

### 2.2. Мирные — в зоне D, не в блоке A (HS-1 закрыт)
Строка `МИРНЫЕ` в блоке A на всех пяти листах **пустая**. Количество мирных в неё
**не пишется** — вопреки словам в видео («вот здесь обычно я пишу количество 4–5»).

Мирные ведутся столбиком в **зоне D**, под блоком A:

```
МИР 1    ИГОРЬ (2)
МИР 2    SLAVA (4)
МИР 3    АНТОН (6)
МИР 4    АНЯЧ (9)
МИР 5    ЭРИК (10)
```

Число мирных = длина этого списка. Отдельного счётчика нет.

Ведущий подтвердил (24.08.2026): строку `МИРНЫЕ` он не заполняет, а в **новом шаблоне
(v2) строки `МИР 1..N` напечатаны** — остаётся вписать номера и имена. То есть в v2 зона D
для мирных не нужна; печатную строку-заглушку `МИРНЫЕ` из v2 можно убирать.

### 2.3. Роли вне печатного списка; жулик и передача карты (HS-4 закрыт)
Роль, которой нет в блоке A (типовой пример — **жулик**), дописывается от руки в зону D;
имя проставляется, когда персонаж проснулся. На пяти имеющихся листах таких ролей нет —
фото-подтверждения пока не было.

**Передача карты жуликом** (ответ ведущего, 24.08.2026): когда жулик забирает чужую
карту, ведущий в блоке A **рядом с ролью жертвы пишет в скобках букву «Ж»** — «жулик стал
этой картой», — а рукописную строку жулика в зоне D **вычёркивает**.

> «Я просто в скобочках рядом с ролью пишу букву „Ж“. То есть жулик стал этой картой,
> а жулика вычёркиваю из списка».

Правило чтения: пометка `(Ж)` у роли ⇒ роль исполняет **игрок-жулик**, а исходный
носитель роли выбыл (`left_unrevealed`, роль жертвы не раскрывается — §3 мастер-плана,
D5/жулик). Зачёркнутая строка жулика в зоне D здесь означает **переход**, а не «роли не
было» — прочерка в клетке имени при этом нет (§2.6). Фото-примера пока нет — при первом
листе с жуликом сверить и добавить в fixtures.

### 2.4. Ростер: кто где сидит (01:16–01:39, 04:41–05:06)
После раздачи карт — 1,5–2 минуты «балагана», за это время ведущий вписывает игроков в
блок B, колонка `№ / ИМЯ`. Номер печатной строки = **место игрока**.

- **С номерками**: место = номерок, начинают с №1.
- **Без номерков**: с угла стола **по часовой стрелке**.

### 2.5. Достройка ролей методом исключения (01:39–02:20)
После ночи знакомства — 2 минуты балагана, за которые ведущий методом исключения
дописывает мирных. Блок A + список мирных становятся полными **только после ночи
знакомства**; частично заполненный блок A на раннем фото — не ошибка.

### 2.6. Выбытие игрока: зачёркивание (HS-2 закрыт частично)
Выбывшего ведущий **зачёркивает**. Зачёркивание встречается в трёх местах, все три
равнозначны:

| Где | Как выглядит |
|---|---|
| Блок A | зачёркнуто имя (`~~НИКИТА(10)~~`) **или** сам печатный ярлык роли (`~~КОМИССАР~~ IGOR (4)`) |
| Зона D | зачёркнута строка мирного целиком (`~~МИР 2   ЛЕОНА (6)~~`) |
| Блок B | зачёркнуто имя в колонке `№ / ИМЯ` |

**Отсюда — главное правило дизамбигуации в блоке A:**

| Клетка «Имя игрока» | Ярлык роли | Смысл |
|---|---|---|
| прочерк «—» | зачёркнут | роли **нет в партии** |
| имя | зачёркнут | игрок **выбыл** |
| имя, зачёркнуто | не важно | игрок **выбыл** |
| имя | не зачёркнут | игрок в игре |

**Ограничение (важно для A1).** Пометка ведётся **нерегулярно**: в `ИГРА N2` зачёркнуты
только дон и мафия, хотя по ночным событиям убиты и мирные `ALEX`, `МИША` — их строки
чистые. Поэтому:

- `struck_out = true` — надёжный сигнал «выбыл»;
- `struck_out = false` — **не** сигнал «жив», а отсутствие информации.

Кто жив на конец партии — восстанавливается симулятором из ночных событий и голосований,
а не из зачёркиваний. **Причину выбытия (выгнан / убит) лист не различает.**

### 2.7. День: голосование палочками (02:20–03:08)
В блоке B, на пересечении строки игрока и колонки `ДЕНЬ N`, ведущий ставит **палочку за
каждый полученный голос**; пятая палочка перечёркивает предыдущие четыре (`卌`).

> «Если в него голосует, ты просто вот здесь ставишь палочку… раз, два, три. Вот тут три
> палочки». (02:34–02:47)

**Цифра справа от палочек — руки за выгон** (ответ ведущего, 24.08.2026; HS-7 закрыт):
палочки — голоса выставления в 30-секундных речах, а когда кандидат вышел на
оправдательную речь и поднятие рук, ведущий дописывает справа **число поднятых рук**
(`卌 ] 5`, `111 ] 3`). Это ровно `day_hands` из контракта мастер-плана.

> «Палочки — это количество голосов… а потом, когда кандидат выходит на оправдательную
> речь и на поднятие рук, я пишу, сколько рук было поднято, и справа подписываю 3, 4 и
> так далее. Но я это делаю не всегда».

**Пометка необязательная** («делаю не всегда»): отсутствие цифры ≠ ноль рук, это `null`.

Остальные пометки:
- **знак `+`** — не отдельный символ; ведущий его за собой не признаёт («наверное, просто
  палочка»). Читать как палочку, при сомнении — `unreadable` (HS-8 закрыт);
- **длинный прочерк «—», протянутый по всем оставшимся колонкам ДЕНЬ** — игрок выбыл, в
  дальнейших голосованиях не участвует (`ИГРА N1`, строка `ТОКИО`; фото `3`, строки
  `SLAVA`, `AMBER`);
- **пустая колонка `ДЕНЬ 1`** — легально: в первый день стол может отказаться голосовать.

### 2.8. Ночь: ночные события (03:12–04:31)
Строки ролей, которых в партии нет, зачёркиваются целиком, и **в каждой из семи ночных
клеток ставится прочерк «—»** — включая ночи, до которых партия не дошла. Это позволяет
отличить `not_applicable` от «ночь не наступила».

В клетке `роль × НОЧЬ N` пишется **имя цели**:

| Строка | Что записывается |
|---|---|
| `ДОН МАФИИ` | кого проверил |
| `МАФИЯ` | в кого стреляли |
| `МАНЬЯК` | в кого стрелял |
| `НАГНЕТАТЕЛЬ` | кого проклял |
| `КОМИССАР` | кого проверил |
| `ДОКТОР` | кого лечил |

**Идентификатор цели — номер места** (ответ ведущего, 24.08.2026; HS-9 закрыт): играют
по номеркам, и ведущий договорился ставить **номер места и в блоке ролей, и в ночных
событиях** («у нас будет всё по номерам»). Имя, если написано, — вторичная сверка.

На пяти листах от 24.08.2026 и раньше в ночных событиях стоят **только имена**, часто
сокращённые (`АМБ`, `8ТОКИ`, `НИКОЛА`) — для старых листов резолв по имени через
`players[]`, неоднозначность → `unreadable` + конфликт на A1, не догадка.

### 2.9. Номер партии — рукописно внизу листа
В нижней трети листа, крупно от руки: `ИГРА N1`, `ИГРА N2`, `ИГРА N3` — либо просто
цифра (`3`, `4`). Печатного поля нет, но **значение на листе есть**, и его надо извлекать
(правка HS-3, см. §6).

## 5. Контракт извлечения (`host_sheet_extraction`)

| Поле | Источник на листе | Правило |
|---|---|---|
| `sheet_template_version` | наличие/отсутствие блоков | `v1` — нет блока фолов; `v2` — есть |
| `players[].seat_no` | номер печатной строки блока B | 1..20; пустые строки в конце — мест меньше |
| `players[].name_raw` | колонка `№ / ИМЯ` блока B | как написано, без нормализации ника |
| `players[].struck_out` | зачёркнутое имя в блоке B / строка мирного в зоне D / строка роли в блоке A | `true` = выбыл; `false` = **нет данных**, не «жив» (§2.6) |
| `roles{role → seat}` | блок A + список мирных зоны D | `seat` берётся **из скобки** `ИМЯ (N)`, не резолвом по имени |
| — | прочерк «—» в клетке имени блока A | роль **отсутствует в партии** → в `roles` не попадает |
| `nights[].actions{role}.state` | клетка блока C | см. таблицу состояний ниже |
| `nights[].actions{role}.target_seat` | имя в клетке блока C | резолв по имени через `players[]`; не резолвится → `unreadable` |
| `day_votes[].tally_count` | палочки в клетке блока B | счёт палочек, пятая перечёркивает четыре; пустая клетка = 0 |
| `game_number_of_evening` | рукописная надпись внизу листа | `ИГРА N<k>` или голая цифра; **есть и в v1** |
| `day_hands[].hands_count` | цифра справа от палочек | руки за выгон на выголосовывании; **необязательна** — нет цифры ⇒ `null`, не 0 (§2.7) |
| `fouls[].count` | — | **только v2.** При `v1` — `[]` |
| роль с пометкой `(Ж)` | блок A | роль исполняет игрок-жулик после передачи карты; исходный носитель выбыл (§2.3) |

### Состояния клетки блока C

| Что в клетке | `state` |
|---|---|
| имя игрока | `performed` + `target_seat` |
| прочерк «—» (обычно вся строка + зачёркнутый ярлык) | `not_applicable` — роли нет в партии |
| клетка пуста, строка роли не зачёркнута | `no_action` — роль есть, но хода нет (мертва, ночь не наступила) |
| написано, но не разбирается | `unreadable` |

**Инвариант 1.** Прочерк в клетке блока C ⇒ прочерк в клетке имени этой роли в блоке A.
Расхождение — конфликт на A1.

**Инвариант 2.** Число заполненных строк `№ / ИМЯ` блока B == числу карт == числу ролей с
именем в блоке A + длина списка мирных зоны D. Нарушение — конфликт на A1.

**Инвариант 3.** Номер места из скобки в блоке A обязан существовать в блоке B, а имя на
этом месте — совпадать. Не совпадает — конфликт на A1, не догадка.

**Инвариант 4 (версия шаблона).** `fouls` существует только в v2; при `v1` — `[]`.
Непустое значение при `v1` — ошибка валидации, а не находка. Негативный тест —
`tests/contract/`, fixture — фото бланка v1.

**Инвариант 5.** `struck_out` не влияет на состав `roles`. Выбывший игрок остаётся в
ростере со своей ролью.
